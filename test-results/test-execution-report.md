## 2. Введение (резюме)

Цель тестирования — проверить соответствие веб-формы регистрации участника археологической экспедиции требованиям технического задания, оценить корректность работы элементов интерфейса, валидации пользовательских данных, отправки и очистки формы.

Тестирование проводилось с использованием чек-листа и набора тест-кейсов. Обнаруженные несоответствия требованиям были зарегистрированы в виде баг-репортов.

## 4. Методология тестирования

Тестирование проводилось вручную на основании требований технического задания.

Использовались следующие методы и техники:

- **Функциональное тестирование** — проверка работы элементов формы и основных пользовательских сценариев.
- **Позитивное тестирование** — проверка обработки корректных входных данных.
- **Негативное тестирование** — проверка обработки некорректных и недопустимых значений.
- **Классы эквивалентности** — разделение тестовых данных на группы с одинаковым ожидаемым поведением.
- **Анализ граничных значений** — проверка минимальных и максимальных допустимых значений, а также значений за пределами ограничений.
- **Исследовательское тестирование** — дополнительная проверка поведения элементов формы и выявление несоответствий требованиям.

Для организации и документирования тестирования использовались:

- Чек-лист;
- Набор тест-кейсов;
- Баг-репорты.

Автоматизированное тестирование не проводилось.

## 5. Список обнаруженных дефектов

В ходе тестирования были выявлены несоответствия фактического поведения формы требованиям технического задания. Все обнаруженные дефекты оформлялись в отдельных баг-репортах.

Для каждого дефекта фиксировались:

- ID;
- Название;
- Шаги воспроизведения;
- Ожидаемый результат;
- Фактический результат;
- Severity;
- Priority;
- Связанный тест-кейс.

### 5.1. Основные категории обнаруженных проблем

| Функциональная область | Обнаруженные проблемы |
|---|---|
| Имя и фамилия | Принимаются недопустимые значения, нарушаются ограничения длины; отсутствуют текстовые сообщения об ошибках |
| Email | Некорректно обрабатываются отдельные невалидные адреса; отсутствуют текстовые сообщения об ошибках |
| Дата рождения | Не соблюдаются ограничения допустимого возрастного диапазона; отсутствуют текстовые сообщения об ошибках |
| Ползунок зарплаты | Значение, шаг изменения и минимальное значение не соответствуют требованиям |
| Загрузка файла | Принимаются файлы неподдерживаемого формата и размером более 5 МБ |
| Дополнительный комментарий | Не соблюдается ограничение максимальной длины |
| Предпочитаемый метод связи | Тип элемента управления и его поведение не соответствуют требованиям |
| Условия использования | Не реализована подсказка при наведении на соответствующий текст |

Полный перечень обнаруженных дефектов представлен в документе [«Баг-репорты»](../bug-reports/bug-reports.md).

## 7. Заключение и рекомендации

В результате проведённого тестирования выявлены несоответствия функциональности формы регистрации требованиям технического задания.

Обнаруженные дефекты затрагивают валидацию пользовательских данных, ограничения вводимых значений, работу отдельных элементов интерфейса, загрузку файлов и взаимодействие с формой.

### 7.1. Рекомендации

1. Исправить дефекты, связанные с нарушением обязательных ограничений и некорректной валидацией пользовательских данных.
2. Устранить несоответствия элементов интерфейса требованиям технического задания.
3. Проверить корректность работы отправки и очистки формы после внесения исправлений.
4. Провести повторное тестирование исправленных сценариев.
5. Выполнить регрессионное тестирование затронутой функциональности.

### 7.2. Итоговый вывод

На основании обнаруженных дефектов форма требует доработки. Окончательная оценка готовности к выпуску может быть дана после исправления дефектов и повторного тестирования.
